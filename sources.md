# Sources: where Lisbon Fringe's events come from

> Kept by researcher.fringe@PrompTugal.dinis (BRIEF.md §5), with researcher.2.fringe@ (work/24). First written 11 November 2026, 10:55 UTC; Meetup, Eventbrite and Partiful rows updated 12:25 UTC. Each source: what it holds, how often it changes, and whether a machine may read it under its terms.

| Source | What it holds | Changes | May a machine read it? |
|---|---|---|---|
| Luma event pages (`luma.com/<slug>`) | One event: name, host calendar, start and end (UTC), place (when public), tickets and price, the organiser's notes (storm changes are written here) | Organisers edit at any time; storm notes appeared on 10 and 11 Nov | Yes, as public web pages, at a person's pace. robots.txt disallows only /social-share, /in/, /company/, /session-*. Luma's terms: access "by any means other than our publicly supported interfaces" is not allowed, so we read the public pages only and **not** Luma's internal JSON API. We publish facts (time, place, status) with a link, never copies of descriptions or images. |
| Luma calendar pages (`luma.com/websummit`, `luma.com/websummit-grauberg`, `luma.com/lisbon`) | Lists of events; the page shows about 20 upcoming events | Hourly or faster this week | As above. The page shows only the next ~20 events, so later days are under-counted. |
| Meetup event pages (`meetup.com/<group>/events/<id>/`) | One event with schema.org data, including `eventStatus` (EventCancelled, EventScheduled) | As organisers edit | **On hold for machines (12:25 UTC).** robots.txt disallows only feeds and a few paths, not event pages, but Meetup's terms (meetup.com/terms and its help-centre copies) return 403 to non-browser clients, so we cannot confirm what they allow. Four Meetup events read one page each before 11:00 UTC stay listed. No new machine reads until a person has read Meetup's terms. |
| Organisers' own sites (e.g. elevon.io) | Their own events | Varies | Per each site's robots.txt and terms; read one page at a time. |
| social.watch@PrompTugal.dinis's fringe file (PrompTugal__News__Website `board/team/social.watch/fringe/events.json`) | Its sweep of public pages | At each of its sweeps | Yes (our estate). Material: every event is re-read at its own page before we publish it. |
| The storm site's `/api/v1/` (https://storm-charles.promptugal.news/api/v1/index.json) | Warnings, transport, decisions | At least hourly while the storm runs | Yes, built for agents. We link to it; we never copy it by hand. |
| Eventbrite | Public event pages and listings | Varies | **No.** Its terms have a section 'Scraping or Commercial Use of Site Content is Prohibited': "You have no right to, and you agree not to, scrape, crawl, or employ any automated means to extract data from the Sites" (quoted from a third-party record of the terms, https://conductatlas.com/platform/eventbrite/eventbrite-terms-of-service/provision/CA-P-039158/scraping-and-automated-data-extraction-prohibited/, and the section title at https://eventbrite.co.uk/tos, both read 12:24 UTC). A person may read a page and give us the link; an agent then reads only the organiser's own site. |
| Partiful | Public event pages | Varies | **No.** Its terms (https://partiful.com/terms, read 12:23 UTC) forbid "any data mining, robots, scraping, or similar data gathering or extraction methods". A person may pass on an event they were sent; we then check the organiser's own public page. |
| Portugal Tech Week (`events.portugaltechweek.com`, `/events.json`) | PTW's own programme feed | Generated 10 Nov 18:13 UTC; stale for 11 Nov (work/24) | Read by researcher.2.fringe@ (work/24); the Luma page wins where they differ. |

Read by me once on 11 Nov (the day page and 10 listings, 14:39 to 14:41 UTC) as a lead; two events were then added from their organisers' own Luma pages, none of the guide's text. No more machine reads until Dinis decides; a person may read it and pass on a link. |
