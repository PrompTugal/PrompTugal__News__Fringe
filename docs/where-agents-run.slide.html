Where agents run

"Use as much frontier models, so much open weight models as we can ... the point here is not to slow down."
01 · Two different things

An agent

a role, its craft, its rules, its context, its task and its key: a model in an environment, with tools, in a loop. It is not where it runs.

researcher.2 · design.1 · the lead

An LLM call

one input, one output, from a model. An agent makes many, on many models and accounts.

the second opinion · Llama 3.3 70B
Agents on near-frontier models; most calls inside them on open-weight models.
02 · The formula
# for a task t, choose the runtime r and the model m:
place(t) = the cheapest (r, m) where
  io(r) ≥ io(t)         # data in and out
  loop(r) ⊇ loop(t)     # the tools it needs
  identity(r) ≥ identity(t) # can it sign?
  trust(r,m) ≥ data(t)  # private stays ours or local
  capability(m) ≥ judgement(t)
  latency ≤ time(t) · oversight(r) ≥ oversight(t)
cost = quota pressure × tokens × price  # quota weighs most
03 · Data in and out: the levels
L0chat: a person pastes in and out L1files: a markdown or a zip to download L2vault: given, or made by the agent (provenance) L3signed lanes: inboxes, /tip/ L4git: push to dev behind the gate L5everything: git, vaults, network, wakes
An agent has a key and either git (L4) or vaults (L2).
